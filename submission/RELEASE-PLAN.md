## Decision

Launch a **developer alpha for people using their own compute**. Announce the
project and its identity-consistency goal now. The short-clip tool is functional
enough for technical experimentation; it is not ready for a broad consumer
launch or claims of convincing facial memory. Preserve the existing two modes,
mark realistic object replacement experimental, and make facial fidelity the
next quality priority.

The repository is already public. Distribution is presently fragmented: main
describes the older motion recipe, codex/validation contains the latest source,
the hosted app is owner-private, there are no published releases, and the
108-second demo predates native motion integration. Fix distribution and show
current cleared evidence before driving people to a promised live service.

Keep owner-funded generation private. A public access toggle alone would let
visitors submit work through the site's shared backend key; no per-visitor
compute budget is implemented. That would consume the included research
credits. The current rules permit local ComfyUI and make a try link optional.
Self-hosting serves the open-source audience without a new billing feature,
queue service, public GPU pool or subscription work.

The developer-alpha gate is **runnable and honestly described**, not a lowering

## What to show and say

Position: **an open video workbench being built around identity consistency**.
Explain two inputs, a short result, raw/composite comparison, and the exact
recipe. The useful public story is measurable progress and reproducible
failures, followed by a real improvement. A finished face should match its
reference and remain stable; stable output with incorrect features fails.

For the first current-native public sample, use original synthetic driving
media and the cleared fictional reference, or newly verified licensed/consented
footage. Retain an existing raw failure in the comparison. The private native
research recording is not cleared for this promotion. Reusing a known synthetic
clip is a public regression/example, not new held-out evidence. A face portrait
or improved still alone is not the motion/fidelity demonstration.

Publish a short native-speed excerpt first, then the final<=2minute demo.
Use X for the initial build thread and one relevant Comfy community channel
after its posting rules are checked. Reuse the same evidence and canonical
repository link. No mass outreach, paid advertising, new brand site or channel
expansion is needed before the deadline. This file authorizes no external post.

Do not claim recovered Genjutsu server code, identical backend architecture,
current performance superiority, exact face memory, arbitrary object tracking,
free unlimited generation, organizer acceptance or a guaranteed prize. Future
outperformance is a goal to assess on matched licensed inputs, not launch copy.

included total**, with$2 held for release/verification rather than exploratory

Each experiment still needs its own frozen inputs, live credit check, hard
call/time/cost bound and stop-on-failure ledger. Fit the face diagnostic and
cleared current-demo run inside the remaining$3; account for image builds,
CPU preparation and downloads. If that estimate fails, reduce runs and publish
the observed limits. Do not raise the$0 cash spend cap, buy credits, or spend
the verification reserve on another failed preparation sweep.

The VACE14B capacity comparison is deferred behind facial consistency. Do not
start a32.29GiB download/build while the release path and focused face test are
still unresolved. The current two modes suffice for this submission.
